# ADR-0009: Public IDs are UUID v7

**Status:** Accepted
**Date:** 2026-11-15
**Requirements addressed:** FR-ORD-016, FR-CHK-008, FR-INV-005, NFR-SEC-006, NFR-L10N-003; dev-standards §5 (Identifiers), §14 item 4

## Context
Public IDs must be opaque and never auto-increment keys. Candidates are UUID v7 and ULID. IDs are created in .NET, Go and Python and stored in PostgreSQL.

## Decision
Use **UUID v7** (time-ordered) for every entity ID exposed in APIs and events, generated by the application. Human-readable order numbers are a separate field (FR-ORD-016). Idempotency keys and event IDs are also UUIDs.

## Options considered
- **UUID v7 (chosen)** — native `uuid` column type, good index locality, supported by .NET, Go and current Python libraries; same format as any other UUID.
- **ULID** — sortable and shorter as text, but no native Postgres type; stored as text or converted.
- **UUID v4** — no time ordering, so inserts scatter across the index.

## Consequences
Easier: one format in all stacks and in the database. Harder: IDs leak creation time (acceptable here). Revisit only if a shorter public format is wanted for URLs.
