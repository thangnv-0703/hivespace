# FEAT-014 spec amendment plan (to discuss in clarify-feature)

> Status: Draft, for discussion in `/clarify-feature FEAT-014` · Date: 2026-11-26
> Related: crawler export plan, `references/hivespace.crawler/PLAN-export-category-tree.md`

## Context
- FEAT-014 is implemented and accepted. Its loader (`Catalog.Api load-categories --source data/category-tree`) is waiting for the owner's final file. `data/category-tree/` still holds a 17-category sample.
- The re-crawl in `references/hivespace.crawler/crawler-state/tiki-v2` is complete:
  - 6,101 categories and 54,992 category–attribute links;
  - full option lists up to 1,000 per attribute, with `totalValueCount` and `valuesTruncated`;
  - 386 distinct attributes and 13,839 distinct options;
  - names and option lists identical across categories; only `isRequired` differs per category (17 attributes).
- Checked against the loader's rules (technical-design §3.5), the raw crawl would be refused or unusable because of:
  - Tiki-only roots and operational attributes;
  - no English names;
  - duplicate option names in 18 attributes (55,080 occurrences);
  - 1.4 GB of repeated option lists;
  - 8 attributes with more than 1,000 options in Tiki.

## Why
Your decisions on 2026-11-26 go beyond the agreed spec:
- the 8 long-list attributes should let a seller pick one of the 1,000 options **or** type their own value;
- option lists are defined once per attribute, not per category.

BR-014-8 says an attribute is a list **or** free text, never both. So the spec must be reopened (status back to Draft) and signed off again before the design and loader change.

## Proposed changes (input to the discussion, not decided)
1. **New attribute behavior, "open list":**
   - a list attribute may also accept the seller's own text;
   - the file marks it (`allowsCustomValue`);
   - amend BR-014-8 and BR-014-9, and FR-CAT-020 in the SRS (new SRS version, RTM row).
2. **Reload rules (BR-014-6 / BR-014-7):**
   - closed → open counts as loosening and is allowed;
   - open → closed counts as tightening and is refused.
3. **New acceptance criteria:**
   - the attribute detail shows whether own text is allowed;
   - an open-list attribute still lists its options in file order;
   - loosening and tightening behave as in item 2.
4. **FEAT-012 impact:** a product's value for an open-list attribute is either an option id or text. FEAT-012's spec is Draft, so it takes a matching amendment (BR-012-7, AC-012-1.x).
5. **For detailed design (not business, recorded in feature-spec §7):** a shared attributes file (option lists defined once), a new `AllowsCustomValue` column, the `allowsCustomValue` field in the contract, and two new file problems (`attributes.unknown`, `attribute.duplicate_key`).

## Questions to raise in the discussion
- Q-A1: Which attributes are open lists? Proposed: the 8 with more than 1,000 options (brand, author, colour/pattern, supplier, distributor, publisher, compatible device, size). Should brand be required where Tiki requires it?
- Q-A2: Which 1,000 options are offered? The crawl holds the alphabetical first 1,000 (brands A–C). Options:
  - keep them;
  - rank by use in the crawled product bundles;
  - start with no options (open text only).
- Q-A3: Can typed text become an option later (a seller-typed brand promoted to the list)? Or is that out of scope?
- Q-A4: Is any check applied to typed text (length, cleaning like BR-014-11)? Is it shown to buyers as entered?
- Q-A5: Operational attributes and Tiki-only roots stay the owner's filtering in the file (BR-014-1). Confirm the lists in the crawler export plan (B1).
- Q-A6: Attributes on the 23 non-leaf categories whose child leaves have none: should the file copy them down to those leaves? Proposed: yes; the loader is unchanged (D-5).
- Q-A7: English names: generated by an LLM and accepted as is (BR-014-4, Q16 already agreed). Confirm the translator choice (crawler export plan, B2).

## Output of the discussion
- An amended `feature-spec.md` (Q&A log, BR/AC changes, §6 SRS amendments, signed off), and the SRS, use cases and RTM updated.
- Then `/detailed-design` amends `technical-design.md` and `tasks.md`, and `/feature-implementation` builds the loader changes. These are separate runs.
